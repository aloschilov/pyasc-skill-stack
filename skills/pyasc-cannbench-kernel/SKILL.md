# pyasc v2 CANNBench kernel workflow

Use this skill only for the vendored benchmark under
`integrations/cannbench/`. Its compact module contract overrides the generic
standalone-kernel workflow.

## Current v2 snapshot

The CANNBench campaign runtime/source authority is
`compiler-team/pyasc@0a631f70968c3cb7c33ce45330a85768dd5a6f06`. The vendored
catalog, evaluator, overlay, and the local compile/CaModel gates are bound to
this pin; a scope's runner launch records it via `--expect-pyasc-source`. When a
review checks runtime provenance, compare against this pin — do not demand a
different one. `adadd7d66ed0ee16d33d79487bf584899a26ef1e` is the historical
high-level GeLU campaign pin and is **not** CANNBench runtime authority; treat
GeLU-pin prose as historical GeLU guidance, not as the current contract.

Runs kept under other pins (for example `030e9b2c0ce44cbc5f9523e03e131f4a23c23a2d`)
remain evidence for those revisions; do not relabel them, and never demand that
the runtime be changed to satisfy stale pin prose.

Author new high-level candidates like `python/test/asctile/target/`: public
`asctile` types, `@asctile.jit`, tile math, `global_tensor`, `copy_in`/
`copy_out`, and `asctile.range`. Use `asctile.GlobalAddress`,
`asctile.ConstExpr`, and `asctile.float32`, including for annotations/casts.
No authored `inline`/`inline_vf`, low-level `asc`/`asc2` code, custom JIT or
compiler monkeypatch, or long Numerical Recipes/Horner polynomial is allowed
in this high-level campaign. Register code generated by `vf_fusion=True`
from public tile operations is allowed.

## Non-negotiable contract

- Treat `tasks/<op>/proto.yaml`, `golden.py`, and all 20 entries in
  `cases.yaml` as one indivisible specification.
- Produce one `candidate.py` with the exact top-level callable and defaults.
- Use `torch` only for allocation, metadata views, and launches. Numerical work
  belongs in public `@asctile.jit` kernels.
- Import and call `ensure_npu_platform` from `._pyasc_runtime`.
- Record the actual target/platform and qualified resource query. The local
  `Ascend950PR_9599` compiler budget is 253952 B; this does not establish a
  runner's physical resources. Bound launch blocks by available vector-core
  resources and useful tiles, not a fixed 72 or a runner-name suffix.
- For the pinned runtime use `asctile.global_tensor`, `asctile.copy_in`, and
  `asctile.copy_out`; use `real_shape` for tails. Do not substitute the older
  `tensor/load/store` spelling.
- Treat padded lanes as executed lanes: choose an explicit, operation-neutral
  `pad_value` for `real_shape` loads (especially `1` for divisors) so tail
  arithmetic does not create avoidable Inf/NaN exceptions.
- Establish both bare `@asctile.jit` defaults and `@asctile.jit(reuse_alloc=1)`
  baselines. The latter's "legacy implementation" is an internal allocation
  pass, not a legacy API. Keep synchronization ON (`insert_sync=True`).
- Explicitly plan `reuse_alloc={0,1,2}` × `static_alloc={None,False,True}` ×
  `vf_fusion={False,True}`. Record measured, failed, and untested combinations;
  validate UB, correctness, and performance separately. See the
  [JIT matrix and diagnostics](../pyasc-api-patterns/references/api-jit-options.md).
  Test the actual decorator/options in fresh processes: base-first keyword
  discovery has a measured inherited-cache bug, while cold AscTile-first
  probes pass. Call-time extraction uses `self.compiler.options_cls`; this is
  not a blanket JIT failure. No concrete-options adapter or custom JIT.
  `always_compile=True` is a development aid, not a submission requirement.

## Required workflow

1. Read the three task files and summarize every dtype, rank, attribute, list
   arity, special value, and boundary shape. Do not optimize for one example.
   An upstream target test is a useful implementation reference, not evidence
   that its narrower dtype/shape/attribute domain implements this contract.
2. Read [operator patterns](references/operator-patterns.md), selecting only
   the target operator section.
3. Design host dispatch, kernel specializations, tails, dtype conversions, UB
   budget, and numerical behavior before writing code.
   For optimization, read [CANN-sample top-down tuning](../pyasc-api-patterns/references/cann-performance-tuning.md).
   Identify one measured bottleneck; distinguish allocation capacity from
   bandwidth and generated unrolling from observed pipeline overlap.
4. Implement the exact callable. Run `python3 -m py_compile candidate.py` and
   the worker static contract check.
5. Run the exact-v2 local compile gate for that operator as described in
   [local validation](references/local-validation.md). A compile failure is
   measured feedback; repair it and re-run all 20 cases within the assigned
   validation budget. Confirm the runtime and gate actually use the campaign
   pin and public decorator before counting a pass.
6. For numerically sensitive formulas, run the adversarial camodel smoke when
   the native runtime is available. It must exercise both ordinary and
   special-value routes using the task's dtype-specific tolerances. Treat a
   small all-finite smoke as insufficient for promotion.
7. Have a different available model review the task, design, candidate, and
   local report. Record both model IDs, OpenCode session IDs, loaded skill
   source hashes, prompt/design/candidate hashes, and gate results.

Local compilation and CaModel are available in the project environment.
Workers use only preconfigured commands within their time/tool budget, without
installs or source builds unless asked. If unavailable in a worker sandbox,
perform syntax/static checks and report the remaining validation to the
coordinator; do not claim the whole project lacks local validation.

Never claim numerical correctness or performance from the local compile gate.
Only camodel execution can provide local numerical evidence; only CANNBench on
the real NPU is the acceptance/performance oracle. In particular, a VF/reuse
kernel that fits the static UB budget can still trigger a vector-core timeout
on a large case.

## Evidence labels

Use exactly one label for every conclusion:

- `verified-local-compile`: all task routes lower through pinned pyasc v2.
- `verified-camodel-smoke`: the stated representative routes executed and
  matched their golden; scope must list omitted dtypes/shapes/cases.
- `verified-camodel`: outputs were executed and compared to the task golden.
- `verified-cannbench`: official hardware result and case count are recorded.
- `suspected`: evidence is incomplete or the root cause is inferred.

Do not promote a locally qualified candidate into the canonical submission
package without numerical evidence. When a CANNBench run reports case-level
failures, feed those exact case IDs and failure classes into repair; a clean
compile matrix must never override measured numerical failures. Do not spend a
submission credit unless the user explicitly enables remote evaluation.

## Known limitations

Consult [pyasc v2 blockers](references/pyasc-v2-blockers.md) as historical,
revision-specific evidence. Its older adapter/low-level recommendations do not
authorize those routes in the new high-level campaign. Reproduce a suspected
JIT failure using the public decorator and the selected pin. Preserve full case
coverage when a case exposes a compiler limit; never remove or shrink the case
to make a gate pass.
