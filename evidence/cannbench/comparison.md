# CANN Bench: pyasc skill-stack vs leaderboard — full L1 coverage (8/8)

Date: 2026-08-29 (phase 2; pilot was 2026-08-28)

## Setup

- Hardware: Ascend950PR_9599 x 1 (remote box via gcpty), CANN 9.1.0,
  torch 2.10.0+cpu / torch_npu 2.10.0.
- Harness: official cann-bench `run_evaluation.sh`, full scoring
  (compile 20 + accuracy 30 + performance 50 per operator),
  local tasks version 1.0.0.
- Submission: `integrations/cannbench/submission/` — pyasc asc2 JIT
  kernels launched zero-copy on torch_npu device buffers.
- Phase 2 method: the 4 pilot kernels were perf-tuned and the 4 remaining
  L1 operators generated by local opencode workers (GLM-5.2, definite
  prompts) driven by `integrations/cannbench/workers/` with a serialized
  NPU eval queue; only candidates passing 20/20 cases were accepted.
- Leaderboard reference: cannbench.com per-operator API, 2026-08-28
  snapshot, 950PR entries. EasyAsc = solution "CANNBot EasyAsc 450USD
  budget" (rank 1 overall, user ddddwee2), PYPTO = "CANNBOT PYPTO"
  (user ddwe7). Ranges span their multiple scored entries per operator;
  "—" means no 950PR entry for that operator.

Highlights:

- 160/160 harness cases pass — full compile (20) and accuracy (30)
  sub-scores on all 8 L1 operators; the whole remaining gap is kernel
  speed.
- Two operators beat the aclnn baseline outright: MaskedScale (1.63x) and
  ForeachAddcdivScalar (1.28x, above EasyAsc's lower entry at 82.54).
- Gelu (57.79) is within one point of EasyAsc's lower entry (58.62).
- Pilot-op tuning gains (worker campaign, M2): Sigmoid 68.65 → 71.86,
  Exp 69.43 → 71.39, Mish 61.13 → 61.89, Gelu 57.19 → 57.79. The accepted
  candidates mainly added size-dependent tile selection (wide tiles for
  large shapes, narrow tiles to recover core parallelism on small shapes).

## Worker-campaign findings (phase 2)

1. **Definite prompts work, but only with measured facts.** Generation
   succeeded once the prompt contained verified API behavior (which ops
   exist on the remote build, measured UB calibration, measured error
   messages). Guidance based on the newer local pyasc fork was actively
   harmful — e.g. `gm_barrier=True` does not exist on the deployed build
   and cost foreach_norm two iterations.
2. **int8/uint8 masks (MaskedScale).** No vector op accepts int8 tiles
   (not even `.to`); the working path is `asc2.cast(m, asc.float16)` then
   `.to(asc.float32)`. uint8 has no tile dtype at all — host-side
   `mask.view(torch.int8)` reinterpretation plus an in-kernel `+256`
   fixup (in f32) handles bytes ≥ 128.
3. **f16/bf16 mixing is a codegen landmine.** A kernel whose tiles include
   both float16 and bfloat16 fails to compile ("redefinition of 'c0_f16'
   with a different type") whenever anything beyond a bare cast happens at
   16 bits. Safe rule: cast every 16-bit tile straight to f32 and do all
   logic there.
4. **Degenerate SwiGlu layouts.** 2-D copy tiles require a 32-byte-aligned
   last dimension; splitting [1000003, 2] on dim=1 (half-column = 2 bytes)
   needs a host-side `narrow().contiguous()` fallback (metadata ops the
   anti-cheat permits) before a 1-D kernel.
5. **Reductions (ForeachNorm).** Loop-carried scalar accumulators and
   multi-core `asc2.atomic_add` combine were both verified on the target
   and cover per-tensor p-norms for p ∈ {-1, 1, 1.5, 2, 2.5, 3, 4, 5, inf}
   (host selects the reduction form since p is a host float).
6. **DashScope throttling.** Parallel opencode workers hit silent
   rate-limit failures (clean exit, no output); the driver retries within
   an iteration, which recovered every occurrence.

## Caveats

- Leaderboard entries are benchmark v1.1.0 (some older entries v0.3.0);
  the local task set is v1.0.0. Same hardware class (950PR), so speedups
  are comparable but case sets may differ slightly.
- EasyAsc/PYPTO are full 53-operator submissions; this campaign covers the
  8 L1 operators.
- Leaderboard snapshot values move; see
  `leaderboard_ref_20260828.json` for the raw per-operator reference data.

## Follow-ups

- Perf remains the only lever: Mish/Gelu are bounded by long op chains
  (UB budget forces narrow tiles), SwiGlu by the strided split layout,
  ForeachNorm by the reduction structure. Next levers: multi-row 2-D
  tiles for SwiGlu, fused two-stage reduction for ForeachNorm, further
  chain shortening for Gelu-erf.
- Extend the same worker pipeline to L2 operators.
